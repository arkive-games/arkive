# Glimmith tutorial projection

The local preview uses cooked Unreal 4.27 scene data from the installed game. No reference screenshots are used by the map or its markers.

- Export `OverworldMap`, `Overworld_Campaign`, `Welcome`, `Zone01_Intro_Bridge`, `Zone01_Intro_Gate_Revised`, `Zone01_Hamlet`, `Zone01_Cathedral`, `Zone01_Market1`, `Zone01_Town_Main`, `Zone1_Town_Main_Underneath`, `Zone01_Countryside`, `Zone02_Forest_Main`, and `Zone02_SideIsland` as UAssetAPI JSON under the original AGeri paths. Export the two `Module_BrokenFloor_Gothic_00*` blueprints and `StylizedProvencal/Blueprints/BP_Ground_Bricks` under their original paths as well.
- Export the selected submap static meshes using CUE4Parse. The mesh JSON is keyed by imported object name. Each record has `vertices` as local-space XYZ triples from the first readable LOD. Include a flat triangle index array as `indices` for `SM_Scroll_001`, `SM_Plinth_V004`, `Ladder_SM`, and `Base_Ship_Full_Static_SM`. For the ship also include `sections` with `material` (the material interface object name), `FirstIndex`, and `NumTriangles`. Other meshes need only vertices.
- Decode and concatenate `Zone01_Hamlet`'s `Texture2D_1` through `Texture2D_3` as raw 64 by 64 BGRA8 buffers in that order. Decode the textures referenced by Market (11), Town Main (17), Countryside (10), Side Island (3), Forest Main (35), and Forest Fragments (14) landscape components as individual 64 by 64 BGRA8 files named after their texture exports, with a `.raw` extension, in separate directories. Forest Main Part 2 uses 21 planes named `<one-based export reference>-<texture name>.raw`: exports 4014 and 4016 both use `Texture2D_0` but contain different height data. Run `node scripts/project-glimmith.mjs <AGeri directory> <assets directory> <mesh JSON> <Hamlet terrain planes> <Market terrain directory> <Town terrain directory> <Countryside terrain directory> <Side Island terrain directory> <Forest Main terrain directory> <Forest Fragments terrain directory> <Forest Main Part 2 terrain directory>` from `frontend/apps/meta` with the original puzzle files. The generator derives 554 puzzle markers from fifteen windows and keeps three tutorial notes.

The opening view is rotated 59 degrees counterclockwise from the previous axis-aligned view to match the direction of travel in the reference view. It remains a plan view, not a recreation of the gameplay camera. Terrain and actor anchors use the same rotation. The tile grid extends one row upward for Precision, one column rightward for Forest Trailhead, one row upward for Match, and one row upward plus one column rightward for Area Number. The projected origin is explicit, and neither the scale nor the game coordinates changed.

The note and puzzle markers are simplified orthographic renders of `SM_Plinth_V004`. The note adds `SM_Scroll_001` at the tabletop height and orientation from `PuzzleTutorialCube`; the puzzle uses the piece defined in `0049.puz` as a generic glass inlay, not a solution or a per-puzzle texture. The web shading approximates the in-game materials. The front-facing stained-glass window icon is authored for map legibility and is not generated by the projection script. Difficulty badge PNGs are direct texture exports of `DifficultyIndicator_1` through `DifficultyIndicator_7` under `UI/Puzzles/Textures/RulePanelIcons/DifficultyIndicators`. The number comes from the puzzle's `DIFFICULTY` line.

Window coordinates, objective thresholds, and puzzle references come from the stained glass actors listed in the generator. Chinese window names come from the matching `AreaName` keys in `Localization/Game/zh-Hans/Game.locres`. Thresholds are authored values, not save progress. The installed puzzle files supply the board footprints, edge relations, numbered cell clues, and solution borders.

Rose Window cell clues use the original `T_SlashPack_*_coloured` textures from `Puzzles/PuzzleGrid/Textures`. Export the decoded BGRA8 textures as transparent PNGs without removing their in-cell padding. The mapping, checked against puzzle `1434` in-game, is `P1` circle, `P2` square, `P3` triangle, `P4` diamond, and `P5` hexagon.

Polyomino cell clues resolve each `S1` through `S9` from the same puzzle file's `SHAPE` declaration. The SVG draws the occupied cells at the authored orientation, preserving leading spaces, and leaves the solution borders untouched. Town Main also projects the three meshes `Brick_Wall_01_SM` through `Brick_Wall_03_SM`; these supply nearby-height footprints for `1049` and `1245`.

Longer cell identifiers (such as `S10`) are normalized to a two-character placeholder with the full identifier preserved by cell index. This keeps the subsequent cells and vertical borders aligned. Mingle, Forest Trailhead, Match, and Area Number show the authored `SHAPE_BANK` under the solution grid when present. Area Number uses two-character decimal clues; render their values in the original cells without the storage padding (for example, `06` displays as `6`).

Forest Trailhead uses Countryside and Town terrain as well as the Forest Main entrance. Area Number extends the Forest Main projection to its fourteen landscape components and the selected authored rock, masonry, and walkway meshes. The `0230` anchor still uses `Brick_Circle_01_SM` and `sm_RuinSetPiece_CircularA` for support.

Range uses the identity stream `Zone02_ForestFragments`. Export its submap JSON, its seven landscape components' fourteen planes, and the authored rock, masonry, planks, and wooden platforms selected by the generator. The added geometry fits the current grid. The solution panel includes any authored `AREA_AT_LEAST` and `AREA_AT_MOST` header values without changing the solution raster.

SizeSeparation uses the identity stream `Zone02_Forest_Main_Part2`. Export its submap JSON, nine landscape components' indexed planes, and the selected rock and masonry meshes, including the short round ruin pillar at `0824`. The canvas grows by one row north without changing relative positions. The solutions show the authored `ADJACENT_SIZES_DIFFERENT` rule and optional area bounds, including the original wide shape identifiers on `1436`.

Boxy and NonBoxy use the existing terrain grid. Palisade cell clues read their released game's enum values and the `PalisadeIcons` map in `DA_RuleData`: `F0 -> 01`, `F1 -> 02`, `F2 -> 03`, `F3 -> 05`, and `F7 -> 04`. Decode the corresponding `T_Symbol_Palisade_*` textures to PNG without changing alpha, padding, or orientation. The solution panels preserve the original rectangle rule and grid.

Boxy anchor `0479` uses its authored world and plan coordinates. The half-plinth-width plan check reaches the original `SM_Rock_02` outline, but neither the rendered rock nor its exported collision hull satisfied the current height check. Its exception is reported as `projectedSupportMeshes`, not verified `supportMeshes`. The support audit still reports it as unresolved. Neither the terrain nor the actor height is adjusted.

Match uses `Zone02_SideIsland`, including its three 64 by 64 planes (`Texture2D_0`, `Texture2D_4`, `Texture2D_5`), rock meshes and authored brickwork. For a regular puzzle plinth, surfaces outside the center-distance tolerance are also checked against the projected bottom of the half-scale `SM_Plinth_V004` in its placed orientation. This preserves the `0319` rock contact even when the Forest Main landscape also passes the center-distance check.

`PuzzleCube_00Secret` (`0054`) declares `EUnlockCategory::GameCompletion`. `PuzzleCube_06` (`0527`) references it in `puzzleUnlocks`, which is not sufficient on its own. `FinalBossPuzzle` unlocks `FinalNote`, the note with the `WBP_Note_CSides` widget and its crimson-plinth text. The note has `CompleteCampaign` set and supplies the campaign window list that the game-completion unlock routine processes; the bridge window in that list includes `0054`. The drawer identifies the final note without asserting that the two puzzle conditions have been independently tested in a completed playthrough.

Map contours are convex projections of selected meshes, not a full terrain or collision reconstruction. Landscape terrain uses the cooked heightmaps, transforms, visibility masks where present, and paint layer weights. Market, Town Main, and Countryside read the weightmap channel indices from each component and use the separate authored walkways. Cathedral floor modules and the Town/Countryside brick-ground blueprint combine component defaults, individual instance overrides, and the actor's root transform. The script requires a nearby-height footprint within the half-width of the game plinth; this also covers two cathedral plinth origins just off the edge of their broken tiles. Actor anchors are never moved. Upper and lower terrain share one plan view, so its contours do not establish traversability between elevations.

Welcome's boarding plank, dock planks, and four `SM_Bridge` sections retain their authored transforms and connect the ship to the tutorial island. The ship hull, deck, cabin, and port and starboard wing sails use separate footprints to avoid covering the open air between them; the overhead balloon is deliberately omitted from the floor plan. The ladder layer uses the projected mesh triangles to keep gaps between rungs. Floating rocks, walkable-looking surfaces, and open air use contrasting colors, without drawing routes over gaps or claiming to track unlocked traversal.
